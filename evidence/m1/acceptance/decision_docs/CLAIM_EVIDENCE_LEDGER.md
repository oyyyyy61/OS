# Claim-Evidence Ledger

Updated: 2026-07-24. Status values are `supported`, `contradicted`, `open`,
`blocked`, and `superseded`. M1 has passed for its declared scope; historical
results alone still cannot support proposed-system performance claims.

Evidence levels are intentionally non-interchangeable: `unit` proves local
transition behavior, `synthetic` proves declared fixtures and fault models,
`live-diagnostic` proves only the paths observed in a real runtime trace, and
`confirmatory` additionally requires a frozen executable protocol, independent
seed clusters, control precision, exact source/config identity, and complete
row-order conformance. A lower level cannot support a higher-level performance
claim.

## Evidence Rules

1. Every performance number links to raw run IDs, frozen run order, source-state
   hash, configuration, and ledger audit.
2. A mechanism counter may support a claim only when it is derived from the
   canonical ledger and the relevant path has nonzero coverage.
3. Failed, negative, and zero-gain runs remain in the matrix.
4. Paper tables distinguish historical evidence, exploratory runs, and
   confirmatory runs.
5. Official PBKV naming requires official code or author artifact alignment;
   a formula-level reimplementation keeps the `PBKV-formula` label.
